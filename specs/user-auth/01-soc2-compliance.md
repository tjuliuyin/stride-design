# SOC2 合规设计：user-auth（用户注册登录模块）

- 需求来源：实现用户注册登录模块，支持邮箱注册、登录、找回密码；用户数据含手机号和邮箱。
- 日期：2026-06-10
- 阶段：1/5（SOC2 合规设计）

## 1. 需求与数据分析

### 1.1 业务需求概述

本模块为系统的统一身份认证入口，核心功能：

1. **邮箱注册**：用户提交邮箱 + 口令（及手机号）创建账号，邮箱需验证后激活。
2. **登录**：邮箱 + 口令认证，签发会话/令牌。
3. **找回密码**：通过邮箱（或短信）发送一次性重置凭据，用户重设口令。

**用户角色**：终端用户（自助注册/登录）、系统管理员（账号管理、封禁/解封）、运维人员（仅运维系统，不可读明文凭据）。

**系统边界**：注册/登录/找回密码 API 与页面、用户数据库、会话/令牌服务、邮件发送通道、短信发送通道。边界外：业务功能模块（消费本模块签发的身份）。

### 1.2 数据资产清单

| 数据类型 | 示例字段 | 敏感级别 | 生命周期（采集→销毁） |
|---|---|---|---|
| 认证凭据 | 口令（仅存哈希）、密码重置 token、会话 token | 极高 | 注册/重置时采集 → TLS 传输 → 单向哈希后存储 → 重置 token 用后即焚/限时失效 → 账号注销时随账号删除 |
| 个人身份信息（PII） | 邮箱地址、手机号 | 高 | 注册时采集 → TLS 传输 → 字段级加密存储 → 仅用于认证与通知 → 注销后留存期满删除 |
| 安全审计数据 | 登录 IP、User-Agent、登录/重置事件日志 | 中 | 认证事件时产生 → 集中日志存储（脱敏） → 保留 ≥ 1 年后归档/删除 |
| 账号状态数据 | 账号 ID、激活状态、锁定状态、MFA 配置 | 中 | 注册时创建 → 随账号生命周期维护 → 注销时删除 |

### 1.3 第三方依赖与数据共享

| 第三方 | 共享数据 | 用途 |
|---|---|---|
| 邮件服务商（SMTP/API） | 邮箱地址、验证/重置链接 | 注册验证邮件、找回密码邮件 |
| 短信服务商 | 手机号、验证码 | 短信验证/通知（如启用） |

要求：仅共享发送所必需的字段，不共享口令哈希等任何凭据数据；供应商须具备有效 SOC2 报告或等效认证（见 C-14）。

## 2. TSC 准则适用性评估

| 准则 | 适用？ | 理由 |
|---|---|---|
| Security（必选） | ✅ 适用 | 必选；本模块即认证与访问控制核心，CC6/CC7/CC8 直接相关 |
| Availability | ❌ 不适用 | 本需求未包含可用性/SLA 承诺；备份与容灾属平台级事项，列入第 5 节残余风险交接。若登录服务后续被定义为关键 SLA 服务，需补充 A 系列评估 |
| Processing Integrity | ❌ 不适用 | 不涉及交易处理、计费或数据加工正确性承诺；输入校验等需求已由 Security（CC6.1/CC6.6 相关控制）覆盖 |
| Confidentiality | ✅ 适用 | 认证凭据（口令哈希、重置 token）属保密数据，需分级标识、加密保护与到期销毁 |
| Privacy | ✅ 适用 | 收集并存储 PII（邮箱、手机号），触发 P 系列：通知、同意、最小化收集、留存与删除、用户访问、泄露通知 |

## 3. 合规控制项设计

> 编号 C-xx 全文唯一，供 SPEC 阶段追溯引用。

### C-01 凭据安全存储
- **TSC 准则**：CC6.1
- **控制目标**：口令与重置凭据即使在数据库泄露时也不可逆向恢复。
- **设计要求**：
  1. 口令使用 argon2id 哈希（参数不低于 OWASP 推荐：memory 19 MiB、iterations 2、parallelism 1），每用户独立随机盐；禁止 MD5/SHA 系列直接哈希、禁止可逆加密、禁止明文存储。
  2. 密码重置 token：≥128 bit CSPRNG 生成，数据库仅存其 SHA-256 哈希；有效期 ≤ 30 分钟，一次性使用，使用或重新申请后旧 token 立即失效。
  3. 任何日志、错误信息、监控数据中禁止出现明文口令或完整 token（脱敏中间件强制）。
- **验证方式**：代码审查 + 单元测试断言存储格式为 argon2id；数据库抽查无明文/弱哈希；日志扫描规则验证无凭据泄漏；重置 token 复用的自动化测试返回拒绝。

### C-02 口令策略与泄露口令检查
- **TSC 准则**：CC6.1
- **控制目标**：防止弱口令与已泄露口令被设置。
- **设计要求**：
  1. 口令长度 ≥ 12 字符，最大 ≥ 64 字符，不强制定期更换、不强制复杂字符组合（遵循 NIST 800-63B）。
  2. 注册与重置时校验泄露口令字典（如 HIBP k-anonymity API 或本地泄露库），命中则拒绝并提示。
  3. 禁止口令包含邮箱本地部分等账号信息。
- **验证方式**：自动化测试用弱口令/泄露口令（如 `password123456`）注册应被拒绝；配置检查策略参数。

### C-03 多因素认证（MFA）
- **TSC 准则**：CC6.1
- **控制目标**：单一口令泄露不导致账号被接管。
- **设计要求**：
  1. 支持 TOTP（RFC 6238）作为第二因素，用户可在账号设置中启用；管理员账号强制启用 MFA。
  2. TOTP 密钥加密存储（字段级加密，密钥走 KMS）；提供一次性恢复码（哈希存储，单次有效）。
  3. 异常登录（新设备/新地理位置）触发邮箱验证码二次确认（风险自适应）。
- **验证方式**：功能测试覆盖 MFA 启用/验证/恢复码流程；配置检查管理员账号 MFA 强制策略；渗透测试验证 MFA 绕过路径不存在。

### C-04 登录防爆破与防滥用
- **TSC 准则**：CC6.1 / CC6.6
- **控制目标**：阻止口令爆破、撞库与验证码轰炸。
- **设计要求**：
  1. 账号维度：连续失败 ≥ 5 次后递增延迟（指数退避），≥ 10 次锁定 15 分钟并邮件通知用户。
  2. IP/设备维度：登录、注册、找回密码接口限流（如同 IP 每分钟 ≤ 10 次），超限返回 429 并触发 CAPTCHA。
  3. 找回密码发送频控：同账号每分钟 ≤ 1 次、每天 ≤ 5 次；短信验证码同等频控防轰炸。
  4. 认证失败响应统一文案与响应时间（防用户枚举与时序侧信道）：登录失败不区分"用户不存在/口令错误"；找回密码无论邮箱是否注册均返回相同提示。
- **验证方式**：自动化测试模拟爆破触发锁定与限流；响应差异化测试（内容与耗时）验证不可枚举用户。

### C-05 会话与令牌管理
- **TSC 准则**：CC6.1
- **控制目标**：会话凭据不可预测、不可窃用、可及时失效。
- **设计要求**：
  1. 会话 ID/令牌 ≥ 128 bit CSPRNG；Cookie 设置 `HttpOnly; Secure; SameSite=Lax`（或更严格）。
  2. 空闲超时 ≤ 30 分钟，绝对生命周期 ≤ 24 小时（可配置）；登录成功后轮换会话 ID（防会话固定）。
  3. 登出立即服务端失效；修改口令/重置口令后吊销该用户全部活跃会话。
  4. 提供"查看并下线其他会话"能力（至少服务端支持按用户吊销）。
- **验证方式**：自动化测试验证登出/改密后旧令牌失效；Cookie 属性配置检查；会话固定攻击测试。

### C-06 账号注册授权与生命周期
- **TSC 准则**：CC6.2
- **控制目标**：账号开通经过有效身份验证，状态全生命周期受控。
- **设计要求**：
  1. 注册必须完成邮箱所有权验证（点击验证链接或输入验证码）后方可激活；未验证账号 72 小时后自动清理。
  2. 邮箱验证链接：一次性、有效期 ≤ 24 小时、token 哈希存储。
  3. 账号状态机明确：未激活 → 活跃 → 锁定/封禁 → 注销；状态变更全部留痕（who/when/what）。
  4. 管理员创建/封禁/解封账号须经审批操作并记录审计日志。
- **验证方式**：功能测试覆盖状态机各迁移路径；审计日志抽查状态变更记录完整。

### C-07 最小权限与职责分离
- **TSC 准则**：CC6.3 / CC1.4
- **控制目标**：对用户数据的访问遵循最小权限，服务端强制授权。
- **设计要求**：
  1. 服务端 RBAC：终端用户仅能读写自己的资料（对象级权限检查，防 IDOR：所有按用户 ID 的查询强制校验当前会话归属）；管理员角色细分（账号管理 ≠ 日志审计）。
  2. 默认拒绝：未显式授权的接口/资源一律 403。
  3. 数据库账号分离：应用账号仅有业务表 DML 权限；运维/DBA 直连生产库须走堡垒机并留痕；任何角色不可读取明文凭据（本就不存在明文）。
  4. 管理后台操作权限每季度复核一次（流程要求，接口需支持权限清单导出）。
- **验证方式**：横向越权自动化测试（用户 A 的会话访问用户 B 的资源返回 403）；权限矩阵评审；数据库权限配置检查。

### C-08 传输加密
- **TSC 准则**：CC6.1 / CC6.7
- **控制目标**：凭据与 PII 在传输中不被窃听或篡改。
- **设计要求**：
  1. 全站强制 TLS 1.2+（推荐 1.3），HTTP 301 跳转 HTTPS，启用 HSTS（max-age ≥ 1 年，includeSubDomains）。
  2. 禁用弱密码套件（无 RC4/3DES/CBC-SHA1，禁用 TLS 1.0/1.1）。
  3. 服务间调用（应用 ↔ 数据库、应用 ↔ 邮件/短信网关）同样加密（TLS 或 mTLS）。
- **验证方式**：SSL Labs/testssl.sh 扫描评级 ≥ A；配置即代码审查；抓包验证内部链路加密。

### C-09 静态加密与密钥管理
- **TSC 准则**：CC6.1 / C1.1
- **控制目标**：存储中的 PII 与保密数据在介质或库泄露时仍受保护。
- **设计要求**：
  1. 数据库与备份启用静态加密（AES-256）。
  2. 手机号、邮箱实施字段级加密或等效保护；需要检索的字段使用确定性加密或盲索引（HMAC）支持等值查询。
  3. 加密密钥统一由 KMS 管理，按环境隔离，支持轮换（≤ 1 年）；禁止密钥/凭据硬编码于代码或配置文件（CI 中接入 secret 扫描门禁）。
  4. 展示场景默认脱敏（手机号 `138****1234`、邮箱 `l***@gmail.com`），完整值查看需额外权限并留审计。
- **验证方式**：数据库存储抽查密文；KMS 密钥策略与轮换配置检查；CI secret 扫描报告；前端/接口返回脱敏验证。

### C-10 数据销毁
- **TSC 准则**：CC6.5 / C1.2 / P4
- **控制目标**：账号注销或留存期满后，PII 与凭据被不可恢复地删除。
- **设计要求**：
  1. 提供账号注销接口：注销后 PII（邮箱、手机号）与凭据数据在 ≤ 30 天宽限期后硬删除或加密销毁（删除字段密钥即 crypto-shredding）。
  2. 审计日志中保留的标识符替换为不可逆假名化 ID（满足日志保留要求又不留 PII）。
  3. 备份中的已删除数据随备份留存周期自然过期（备份保留 ≤ 35 天），并在恢复流程中加入"已注销账号过滤"步骤。
  4. 未激活账号 72 小时自动清理（与 C-06 联动）。
- **验证方式**：注销后到期扫描数据库与日志确认 PII 不可检索；删除任务执行日志；恢复演练验证过滤步骤。

### C-11 安全事件日志与监控
- **TSC 准则**：CC7.2 / CC7.3 / CC2.1 / CC4.1
- **控制目标**：认证相关安全事件可检测、可追溯、可取证。
- **设计要求**：
  1. 记录事件（结构化 JSON）：注册、登录成功/失败、登出、口令修改/重置申请与完成、MFA 启停、账号锁定/解锁、管理员操作；字段含 who（用户 ID/管理员 ID）、when（NTP 同步的 UTC 时间戳）、where（IP、User-Agent）、what、result。
  2. 日志集中收集至独立日志系统，append-only，应用账号无删除/修改权限；保留 ≥ 1 年。
  3. 日志脱敏：不记录口令、token 原文；手机号/邮箱按 C-09 规则脱敏。
  4. 告警规则：单账号短时多次失败、同 IP 批量失败（撞库特征）、异地登录、管理员批量操作、重置接口调用激增 → 触发告警至安全响应通道。
- **验证方式**：触发各类事件后核对日志字段完备性；尝试以应用账号删改日志应失败；告警规则注入测试事件验证触达。

### C-12 漏洞与依赖管理
- **TSC 准则**：CC7.1 / CC6.8
- **控制目标**：认证模块自身及其依赖无已知高危漏洞。
- **设计要求**：
  1. CI 流水线集成 SCA（依赖漏洞扫描）与 SAST，高危（CVSS ≥ 7）阻断合并；依赖使用 lockfile 锁定并校验完整性。
  2. 上线前对认证接口执行 DAST/渗透测试，覆盖 OWASP ASVS V2（认证）、V3（会话）章节。
  3. 高危漏洞修复 SLA：≤ 7 天；中危 ≤ 30 天。
- **验证方式**：CI 门禁配置与扫描报告；渗透测试报告与修复闭环记录。

### C-13 变更管理
- **TSC 准则**：CC8.1
- **控制目标**：认证模块的代码与配置变更受控、可回溯。
- **设计要求**：
  1. 所有变更经分支 + Pull Request，至少 1 名非作者审查通过且 CI（含 C-12 安全门禁）绿灯方可合并；认证核心逻辑（口令、会话、重置流程）变更需安全角色额外审批。
  2. 生产配置（口令策略参数、限流阈值、密钥引用）以代码/配置中心管理，变更留痕；禁止直接在生产手改。
  3. 紧急变更 48 小时内补提审查记录。
- **验证方式**：仓库分支保护与 CODEOWNERS 配置检查；抽样变更追溯审查与审批记录。

### C-14 第三方通道风险管理
- **TSC 准则**：CC9.2 / P6.1
- **控制目标**：邮件/短信服务商引入的数据共享风险受控。
- **设计要求**：
  1. 仅向通道传递发送必需字段（收件地址/手机号 + 消息内容）；禁止传递口令哈希、内部用户 ID 之外的额外 PII。
  2. 通道 API 凭据最小权限（仅发送权限）、存于 KMS/密管系统、支持轮换；调用走 TLS。
  3. 选型要求供应商具备有效 SOC2 Type II 报告或等效认证，签署 DPA（数据处理协议）；在隐私政策中披露该共享（联动 C-15）。
  4. 邮件中的验证/重置链接不含 PII 明文参数（仅含不透明 token）。
- **验证方式**：集成代码审查传参白名单；供应商合规证明归档检查；链接参数审查。

### C-15 隐私通知与同意
- **TSC 准则**：P1.1 / P2.1
- **控制目标**：用户在提供 PII 前知情并同意收集与使用目的。
- **设计要求**：
  1. 注册页明示隐私政策链接，政策说明：收集字段（邮箱、手机号）、目的（账号认证、安全通知、找回密码）、第三方共享（邮件/短信服务商）、留存期限、用户权利与联系渠道。
  2. 注册须勾选同意（非默认勾选），同意记录（版本号 + 时间戳 + 用户）持久化存储。
  3. 隐私政策更新后，下次登录提示重新确认；用户可在设置中撤回非必要用途同意（如营销通知），撤回即时生效。
- **验证方式**：UI 走查注册流程；数据库核查同意记录字段；撤回同意后通知发送测试。

### C-16 收集最小化
- **TSC 准则**：P3.1
- **控制目标**：仅收集认证功能必需的个人信息。
- **设计要求**：
  1. 注册必填项仅邮箱 + 口令；手机号设为可选（用于增强找回与通知），不得作为注册强制项，除非业务方提供合规依据并在政策中说明。
  2. 不采集与认证无关的字段（生日、地址等）；前端表单与后端 schema 双侧约束。
- **验证方式**：接口 schema 审查；提交多余字段的请求应被忽略或拒绝的自动化测试。

### C-17 用户访问、更正与删除权利
- **TSC 准则**：P4.3 / P5.1 / P5.2 / P7.1
- **控制目标**：用户可查询、更正、删除自己的个人信息。
- **设计要求**：
  1. 账号设置页提供：查看本人邮箱/手机号、修改手机号、换绑邮箱（新旧双向验证）、注销账号（触发 C-10 删除流程）。
  2. 更换邮箱/手机号需重新验证所有权（验证码/链接），保证数据质量（P7）。
  3. 敏感操作（换绑、注销）前要求重新认证（输入口令或 MFA）。
  4. 注销流程明确告知影响与宽限期，宽限期内可撤销。
- **验证方式**：功能测试覆盖查看/更正/换绑/注销全流程；未重新认证执行敏感操作应被拒绝。

### C-18 数据泄露检测与通知准备
- **TSC 准则**：P6.3 / CC7.3 / CC7.4 / CC2.3
- **控制目标**：发生 PII 或凭据泄露时可及时检测、评估并通知受影响用户。
- **设计要求**：
  1. C-11 的告警接入事件响应流程：定义认证数据泄露事件分级（凭据库泄露 = P0）。
  2. 系统具备按时间范围导出受影响用户清单的能力（基于审计日志），支撑通知义务。
  3. 提供批量强制重置能力：管理端可对指定用户集合吊销全部会话并强制下次登录重置口令。
  4. 用户通知模板与渠道（邮件）预置，事件确认后 72 小时内可发出通知。
- **验证方式**：事件响应桌面演练记录；批量吊销/强制重置功能测试；导出受影响用户清单的演练。

## 5. 残余合规风险与说明

无法在本需求范围内闭环、需组织级或平台级承接的事项：

1. **Availability 缺口**：本模块未纳入 A 系列评估。若登录服务后续承诺 SLA 或被认定为关键服务，需补充容量监控、备份恢复（RTO/RPO）与演练设计；当前备份加密要求已在 C-09/C-10 中顺带覆盖，但恢复演练未定义。
2. **组织级流程**：安全意识培训、董事会监督、人员入离职访问审批（CC1 系列）、季度权限复核的执行（C-07 第 4 条仅提供技术支撑）需由组织流程承接。
3. **物理安全（CC6.4）**：假定部署于公有云，依赖云厂商 SOC2 报告，需采购/合规团队每年获取并评审云厂商报告。
4. **法域差异**：若用户覆盖 GDPR/中国个保法等法域，72 小时泄露通知（C-18）、数据出境等要求需法务确认，可能严于本设计基线。
5. **威胁建模衔接（CC3）**：本文档识别的控制项需在下一阶段（STRIDE 威胁建模）逐项映射验证覆盖度，未覆盖的威胁须回补控制项。
