# SOC2 Trust Services Criteria 控制项知识库

> 供 `soc2-compliance-designer` 子代理使用。依据 AICPA TSC（2017，2022 修订版要点）整理，聚焦可转化为软件设计要求的控制点。

## 适用性判定速查

| 准则 | 是否必选 | 触发条件 |
|---|---|---|
| Security（CC 系列） | **必选** | 所有需求 |
| Availability（A 系列） | 可选 | 有可用性/SLA 承诺、关键在线服务 |
| Processing Integrity（PI 系列） | 可选 | 交易处理、计费、数据加工正确性敏感 |
| Confidentiality（C 系列） | 可选 | 处理商业机密、客户保密数据 |
| Privacy（P 系列） | 可选 | 收集/使用/存储个人信息（PII） |

## Security — Common Criteria（必选）

### CC1 控制环境
- CC1.1-1.5：组织层面（诚信、董事会监督、职责分配、胜任能力、问责）。软件设计层面通常体现为：职责分离（开发/运维/审批分离）、最小权限的角色设计。

### CC2 信息与沟通
- CC2.1：获取并使用与内控相关的高质量信息 → 设计要求：系统须产生足以支撑监控的运行与安全数据（结构化日志、指标）。
- CC2.2/2.3：内外部沟通 → 设计要求：安全事件通知机制、用户可见的安全/隐私政策入口。

### CC3 风险评估
- CC3.1-3.4：设定目标、识别与分析风险（含舞弊）、评估重大变化 → 设计要求：新功能上线前完成威胁建模（与 STRIDE 阶段衔接）。

### CC4 监控活动
- CC4.1/4.2：持续监控与缺陷沟通 → 设计要求：安全监控告警（异常登录、权限变更、批量数据导出）、漏洞扫描纳入流水线。

### CC5 控制活动
- CC5.1-5.3：选择并部署控制活动、技术通用控制、通过政策落地 → 设计要求：本needs文档中所有技术控制的总纲。

### CC6 逻辑与物理访问控制（软件设计核心）
- **CC6.1** 逻辑访问安全：身份标识唯一、强认证（口令策略 + MFA）、凭据安全存储（argon2id/bcrypt/scrypt）、传输与静态加密（TLS 1.2+/AES-256）、密钥管理（KMS，禁止硬编码）。
- **CC6.2** 注册与授权：账号开通须经授权审批；账号生命周期管理（入职/转岗/离职）。
- **CC6.3** 访问权限管理：RBAC/ABAC，最小权限，定期权限复核，职责分离。
- **CC6.4/6.5** 物理访问与资产处置：云环境下转化为对云厂商 SOC2 报告的依赖声明 + 数据销毁流程（删除时安全擦除/加密销毁）。
- **CC6.6** 边界防护：网络分段、防火墙/安全组、WAF、入站流量限制。
- **CC6.7** 数据传输与移动介质：传输加密、下载/导出控制、防数据外泄。
- **CC6.8** 防恶意软件：依赖完整性校验（lockfile、签名验证）、运行环境防护。

### CC7 系统运营
- **CC7.1** 漏洞管理：依赖漏洞扫描（SCA）、配置基线检测。
- **CC7.2** 安全监控：安全事件日志（认证、授权失败、敏感操作）集中收集，异常检测。
- **CC7.3/7.4** 事件评估与响应：事件分级、响应流程、取证所需的日志完整性（防篡改、时钟同步、保留期限）。
- **CC7.5** 事件恢复：恢复流程与演练。

### CC8 变更管理
- **CC8.1**：变更须经授权、设计、开发、测试（含安全测试）、审批后部署；基础设施即代码与配置变更同样受控；紧急变更事后补审。

### CC9 风险缓解
- CC9.1：业务中断风险缓解（与 A 系列衔接）。
- CC9.2：供应商与第三方风险管理 → 设计要求：第三方集成的最小权限 API 凭据、数据共享协议。

## Availability（A 系列）
- **A1.1** 容量管理：容量监控与弹性扩展设计。
- **A1.2** 环境保护、备份与基础设施恢复：自动备份、备份加密、异地副本、RTO/RPO 定义。
- **A1.3** 恢复测试：备份恢复演练可执行。

## Processing Integrity（PI 系列）
- **PI1.1** 处理目标相关信息定义。
- **PI1.2** 输入完整性：输入校验、重复提交防护（幂等）。
- **PI1.3** 处理完整性：事务一致性（ACID/补偿）、处理失败的检测与纠正。
- **PI1.4** 输出完整性：输出与预期一致、对账机制。
- **PI1.5** 存储完整性：数据存储期间防未授权修改（校验和、审计跟踪）。

## Confidentiality（C 系列）
- **C1.1** 保密信息标识与保护：数据分级分类、保密数据加密与访问限制。
- **C1.2** 保密信息销毁：到期销毁流程、销毁证明。

## Privacy（P 系列，处理 PII 时）
- **P1** 通知：隐私政策、收集目的告知。
- **P2** 选择与同意：同意获取与撤回机制。
- **P3** 收集：仅收集必要信息（最小化）。
- **P4** 使用、留存与处置：限定目的使用、留存期限、到期删除、用户删除请求（RTBF）。
- **P5** 访问：用户查询/更正自己的个人信息。
- **P6** 披露与通知：第三方共享控制、数据泄露通知。
- **P7** 质量：个人信息准确、完整、相关。
- **P8** 监控与执行：隐私投诉处理与合规监控。

## 输出设计要求时的常见技术映射

| 控制主题 | 典型设计要求示例 |
|---|---|
| 认证 | 口令策略（长度≥12、泄露口令字典检查）、MFA、登录失败锁定、会话管理（超时、并发控制、登出失效） |
| 授权 | 服务端强制 RBAC、默认拒绝、对象级权限检查（防 IDOR） |
| 加密 | 传输 TLS1.2+、静态 AES-256、密钥走 KMS、敏感字段级加密 |
| 审计 | 记录 who/when/what/result、防篡改（append-only/签名）、保留 ≥1 年、日志脱敏 |
| 数据生命周期 | 分级分类、留存策略、删除即销毁、备份同样受保护 |
| 变更 | CI/CD 中强制代码审查 + 安全测试门禁、生产配置变更留痕 |
